## First-party pack (`skills/first-party/`)

Unlike every other pack, this one has no upstream and no pinned commit — it is authored in this repo, so it carries no vendor-drift risk and no obligation to stay byte-identical to anything.

**`proactive-agency`** — an always-on execution posture: do the work rather than describe it. It is delivered via `metadata.sessionStart: true` + `priority: 10`, the same mechanism `vercel/knowledge-update` uses, which means it is *injected* rather than trigger-matched. That choice is deliberate: this repo's documented dominant defect class is over-triggering and cross-pack trigger collision, and a session-start skill adds **zero** trigger surface. Its `pathPatterns`/`bashPatterns`/`importPatterns` are explicitly empty for the same reason.

**`skill-library-audit`** — audits a multi-vendor skill library for routing pathology, and ships a runnable 2,991-line analyzer at `scripts/audit_skill_library.py` (stdlib + PyYAML, no network).

It exists because this repo kept paying for the same defect class. `SOURCE.md` already documents two cross-pack collisions found *by hand, after landing*; a third (`vercel/ai-sdk` overlay drift) was found by this analyzer on its first real run and is fixed in the same commit that added it. The skill treats a library as simultaneously a **routing table** (which skill claims this file/import/command/prompt?) and a **retrieval index** (which document matches this query?), and applies the failure theory both fields already have.

Sixteen detectors, honestly split between **exact** (SK001 invalid frontmatter, SK002 duplicate names, SK004 SKILL.md↔overlay drift, SK005 dangling routes, SK006 self-routes, SK007 chainTo cycles, SK013 unreachable rules) and **heuristic** (SK003 schema-outlier placement, SK008 IDF/Bayes greediness, SK009 territory claims, SK010 shadowing, SK011 dead guard tokens, SK012 vendor steering, SK014 prose references, SK015 unscoped, SK016 priority inversion). Heuristic findings carry their evidence and are explicitly marked for human review; the skill instructs the agent to fix exact findings and escalate heuristic ones rather than guess.

Two ideas do real work rather than decorate:

- **Bayes at scale.** A trigger is a diagnostic test for "is this the right skill?". At N=90 the prior is 1.11%, so a trigger with 90% sensitivity and 95% specificity has a posterior of just 16.8% — five of six firings wrong. This is why a description that is fine in a 5-skill plugin becomes destructive here, and why greediness is scored against library size rather than a fixed word count.
- **IDF anchor scoring.** A description term's trigger value is inversely proportional to how many skills share it. Plain bag-of-words IDF failed in testing (at N=89 nearly every description contains some rare *English* word, so everything scored as maximally specific); it now indexes only identifier-shaped anchor terms.

Validation was adversarial in both directions and is the reason to trust it. A fixture library reproduces all ten historical defect classes plus a clean control pack that must emit zero findings — all ten fire, control is silent, no crashes on hostile input (empty files, missing frontmatter, broken overlays, unclosed regex groups, non-numeric priority). Then a red-team pass cut the real-library output from **152 findings to 20** by suppressing house conventions it had misread as defects: self-targeting `chainTo` is this library's documented idiom for "stay here" (56 sites, not 56 bugs), 65 of 89 skills legitimately have no routing metadata, and the priority-inversion check was firing on the *post-fix* direction. Three soundness bugs were found and fixed during that pass, each documented in-code — most instructively, literal extraction from regexes *under*-approximates requirements, so reading `@vercel/(postgres|kv)` as merely requiring `@vercel/` "proved" it shadowed `@vercel/connect`; restricting the broad side cut 253 bogus findings to 18.

Known limits are stated in the module docstring rather than hidden: SK012 is blind to vendors absent from its product lexicon, SK011 cannot distinguish a typo from a package the library simply never discusses, and SK003 assumes the majority key placement is correct — it would confidently accuse the one correct skill in a library where it is not.

**Stale calibration figures — flagged, not silently rewritten.** The skill's teaching sections are pinned to the library as it stood at **N = 89** (`SKILL.md` lines 54, 89, 93–115, 135, 212; `scripts/audit_skill_library.py:36,1949`). The library is now **N = 106 / 12 packs / 190 routing rules**, and the analyzer emits **17 findings (2/6/9)**, not the *"20 findings — 4 high, 7 medium, 9 low"* that `SKILL.md:66` still advertises as a tuned run over this repo. Most of those figures are explicitly captioned *"use your own corpus's numbers, not these"* and the posterior tables are internally derived from N = 89, so re-pointing one line would make the section inconsistent with the arithmetic around it. Whoever next revises that skill should re-derive the whole calibration block at once rather than patch a number at a time. Left as-is deliberately: the direction of every conclusion is unchanged (a larger N tightens the required FPR, it does not loosen it), so the guidance is conservative, only the arithmetic is dated.

Design notes worth preserving if this file is ever edited:

- The load-bearing content is the five-step gate at the top. Everything below it is a branch of that gate; deleting the gate guts the skill.
- The **confirm-first table is deliberately narrow** and paired — each row names both the action needing confirmation and its permitted near-twin (e.g. *deploy to production* vs *preview deploys*; *destructive DB ops* vs *writing and locally applying migrations*). Widening this table is the main way to break the skill: every extra row is a pre-authorized excuse to hand work back to the user, which is exactly what it exists to prevent. The catch-all reversibility test (`git checkout` / `git revert` / delete a file / local rollback ⇒ just do it) is what keeps unlisted cases defaulting to action.
- Clarifying questions are explicitly *unlimited* — the user's request was to minimize handoffs, not questions. The Legitimate/Illegitimate table encodes that split; do not "tighten" it into a general discouragement of asking.
- It was drafted three ways (rule-system, anti-pattern catalog, decision-procedure) and scored by three judges — one scoring specifically for whether lines are self-detectable mid-response rather than exhortation, one for whether the safety boundary could be abused as a laziness loophole, one for context density. It is injected into every session, so any future edit should hold the same bar: no line that a model would nominally agree with but not act on.
